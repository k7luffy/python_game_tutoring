Review · variables

Quick Revision – Variables

predict_me.py
coins = 50
coins = coins - 1
print(coins)      # 49

A labelled box

coins is the name. 50 is the value inside.

Read it right to left

Take the current coins, subtract 1, put the result back in the box.

The maze uses this exact rule: every step costs 1 coin.
Ask pairs to predict the output before revealing it; the answer is 49. This is the deliberate misconception: coins = coins - 1 looks impossible, but the right side is calculated first. Every successful step in the maze runs this same idea. Students will meet it again in the loop tracing slide.
Review · comparisons

Quick Revision – Comparison Operators

OperatorQuestion it asksExample
==Are they equal?coins == 30
>Is the left bigger?coins > 30
<Is the left smaller?coins < 30
>=At least as big?coins >= 30
compare.py
coins = 34
print(coins >= 30)   # True
print(coins == 30)   # False
= puts a value in a box. == asks a question. Do not mix them up.
A comparison always answers True or False. Read each operator as a question: equal, bigger, smaller, or at least as big. The boss uses coins >= 30, so students must see that exactly 30 passes. Stress the difference between one equals sign for assignment and two for comparison; this is the most common slip in the exit ticket.
Review · decisions

Quick Revision – If-else

decide.py
if coins >= 30:
    print("Ready to attack!")
else:
    print("Keep collecting!")

True

The indented lines under if run.

False

Python jumps to the indented lines under else.

Colon at the end. Indent the branch. Only one branch runs.
Trace it: with 34 the first branch runs; with 20 coins the else branch runs.
Trace the snippet twice, first with 34 and then with 20. Ask which branch runs and why. Point out the colon and the indentation; those are the two errors students make most often. Tell them this exact pattern will return in the Super Attack stage, once they have earned the coins in the maze.
Review quiz · 3 questions

Review Quiz

Choose an answer. Wrong answers can be tried again.

After these lines, what is coins?
coins = 20 · coins = coins + 5

The right side is calculated first: 20 + 5 = 25, then stored back in coins.

With coins = 30, what does coins >= 30 give?

>= means at least, so 30 counts. The comparison gives the value True.

If the if condition is False, which lines run?

Exactly one branch runs. A False condition skips the if body and runs the else body.

Give students a minute to answer all three, then reveal. Ask them to say the rule, not just the letter. The three rules are: assignment calculates the right side first, comparisons answer True or False, and a False if condition jumps to else. Reset all quizzes with the R key before the next class.
Input · asking a question

Asking for Input with input()

name.py
player_name = input("What is your name? ")
print("Hello", player_name)

The prompt

The text inside the brackets is the question the player sees.

The answer

The player's typing comes back from input().

The variable

player_name stores the answer so we can use it later.

Sample run: the prompt appears, the player types Nova, and the program prints Hello Nova.
Run this live if possible: the game pauses and shows a dialog for the answer. The important idea is that input() hands back whatever the player typed. Ask what would happen if the player typed nothing and pressed Enter; the variable would hold an empty string. Keep the focus on storing the answer, not on formatting.
Input · text to number

Turning Text into Numbers with int()

steps.py
steps_text = input("How many steps? ")
steps = int(steps_text)
print(steps + 1)

input() gives text

Even 7 arrives as the text "7", not the number 7.

int() converts

int("7") is the number 7, ready for maths and comparisons.

Bad input

int("seven") cannot convert, so Python reports an error.

Nest the calls: int(input("How many steps? ")) asks first, then converts the answer.
Demonstrate the difference: "7" plus 1 would join text, while 7 plus 1 gives 8. Then type seven instead of 7 to show the friendly Value Error. Explain that int() only works on text that looks like a whole number. The nested form is worth showing because it is shorter, but students may use two lines if that is clearer. The game fixes weapon_power at 5, so the Create mission does not need this conversion; the skill still matters whenever a program asks for a number.
Input · putting it together

Putting Input Together

my_explorer.py
player_name = input("What is your name? ")

print("Welcome,", player_name)
1

Ask for the name. Store the text in player_name.

2

input() gives text — perfect for a name, so no conversion is needed.

3

Print the welcome. The game sets weapon_power to 5.

Sample run: the player types Nova and the console shows Welcome, Nova. Weapon power stays 5.
This is the worked example for the Create mission, but students will type their own version from an empty editor in the game. Walk through the three steps and point out that the answer from input() is already text, which is exactly what a name needs. The game supplies weapon_power (fixed at 5) for this mission, so there is no second question and no int() here. Ask where int() would be needed if the program asked for a number instead.
Input quiz · 3 questions

Input Quiz

Three checks on input() and int().

What type of value does input() always return?

input() always hands back text, even when the player types digits.

What is int("7")?

int() converts number text into a real number, so "7" becomes 7.

Which line asks for a number of steps and stores a number?

The inner input() asks, then the outer int() converts the answer before storing it.

Ask students to explain their choice in one sentence before revealing. The rules: input returns text, int converts number text, and the inner call runs first. Option a on question three is the classic nesting mistake; use it to show that int() cannot be given a question as its argument.
Loops · the problem

Why Loops? The Copy-Paste Problem

copy_paste.py
move_one_step_right()
move_one_step_right()
move_one_step_right()
move_one_step_right()

It works

Four lines, four steps forward, four coins spent.

But it does not scale

Twenty steps means twenty lines. One typo hides in the middle.

A loop lets us say do this again once, instead of repeating the line by hand.
Predict: how many lines would 40 steps need without a loop? Forty. The next slide does it in two.
Let the repetition feel silly. Ask the class what happens when the route needs forty steps, or when we change the step count from four to twelve. The point is not that repetition is wrong, but that it hides mistakes and makes edits expensive. This sets up the for loop as a better way to express the same action.
Loops · the tool

Introducing for and range()

first_loop.py
for i in range(3):
    move_one_step_right()
print("Done")

The for line

Ends with a colon. It says: repeat the indented lines below.

range(3)

Counts 0, 1, 2 — that is three repeats, not four.

The body

move_one_step_right() is indented, so it belongs to the loop.

range(5) repeats five times. The number is a count, not the last value.
Type the two-line loop and run it four times, changing the count each time. Ask students to predict the number of steps for range(5) before running. Emphasise the colon and indentation; a missing colon or a lost indent is the usual failure. The print line is not indented, so it runs once after the loop.

Start: 30 coins

Each pass costs exactly one coin.

Three passes

Three steps, three coins, and i goes 0, 1, 2.

The loop body does not run for i = 3. The count is already finished.
Trace the loop on the board before running it. Cover the coins column and ask the class to fill it in. The key insight is that range(3) gives three passes numbered from zero, and each pass executes the whole indented body once. This trace is the mental model students need for planning maze routes.
Loops · game practice

Your First Game Loop

corridor.py
for i in range(8):
    move_one_step_right()
print("Coins left:", coins)

8 repeats

Eight steps forward. Eight coins spent.

Change one number

Range(12) walks twelve steps without adding a line.

Indent the body

Only the indented lines repeat. The print runs once.

This is already a maze program. On Level 1 the corridor is straight — count the steps, then loop.
Have students predict the coins after eight steps, then after changing the count to twelve. The print statement is deliberately outside the loop, so it runs once at the end. Remind them that every move costs a coin and points the robot that way: a loop that only moves right walks into a wall unless the corridor is straight. Level 1 is the safe place to test this.
Loop quiz · 3 questions

For Loop Quiz

Three checks on range(), colons and coin costs.

How many times does range(5) repeat the body?

range(5) counts 0, 1, 2, 3, 4 — five passes, not five as a stopping value.

What must the for line end with?

The colon opens the loop body. The indented lines below it are repeated.

A loop that moves once per pass, four passes, costs how many coins?

Each move costs 1 coin, and four passes make four moves: 4 coins.

Ask for the rule behind each answer. The three rules: range(n) means n passes, a for line ends with a colon, and every move costs one coin. Question three links the loop count directly to the maze budget, which is the skill students need when a level starts with fewer coins than the route's length.
Functions · the idea

What Is a Function?

A named recipe

A function is a block of code with a name. Write it once, use it whenever you need it.

Define, then call

def creates the function. Writing its name with brackets calls it.

No return needed

Our game functions do something on screen. They do not send a value back.

cheer.py
def cheer():
    print("Go robot!")

cheer()
cheer()
The definition is the recipe. The two calls are two meals — same code, used twice.
Use a non-game example first so the syntax is not hidden by the maze. Run the cheer program and point out that the word cheer appears twice because the function is called twice. Ask what would happen with no call at the bottom: nothing is printed, because defining a function does not run it.
Functions · define and call

Defining and Calling a Function

move_three.py
def move_right():
    for i in range(3):
        move_one_step_right()

move_right()

Definition

def move_right(): names the recipe. The body is indented.

Call

move_right() at the bottom runs the recipe once.

Order matters

Define the function before you call it.

This function always moves three steps. The next slide gives it a slot so it can move any number.
Trace the definition line by line, then the call. Ask why the call is not indented: it is top-level code, outside the function. Delete the call and run again to show that nothing happens. This is the moment to establish define versus call, because the next slide adds a parameter on top of the same skeleton.
Functions · parameters

Adding Parameters to Functions

move_right.py
def move_right(steps):
    for i in range(steps):
        move_one_step_right()

move_right(3)
move_right(8)

Parameter

steps is a slot in the definition. It has no value until the function is called.

Argument

3 and 8 are the values that fill the slot.

range(steps)

The loop count changes with the argument, so one function fits many routes.

Same function, two different jobs: 3 steps, then 8 steps.
Trace the first call with steps equal to 3 and the second with steps equal to 8. Show that the definition does not change. Ask students to write the call for five steps before revealing it. The key vocabulary is parameter in the definition, argument in the call; keep using both words so the distinction sticks.
Functions · build it

Building move_right(steps)

my_toolkit.py
def move_right(steps):
    for i in range(steps):
        move_one_step_right()

move_right(2)
move_right(8)
print("Coins left:", coins)

2 + 8 = 10

Two calls, ten steps, ten coins.

Reuse

The same helper works in any corridor. Change the argument, not the code.

One coin each

Every move costs 1 coin, so the step count is the budget.

This helper is yours to use in the maze. You still choose the directions and the step counts.
Run the program and check the console: ten coins spent. Ask why the function is written before the calls. Point out that the helper is a tool, not an answer: it moves whatever number of steps you ask for, but the student still has to plan the route around walls and supplies. This distinction matters for the next game section.
Function quiz · 3 questions

Function Quiz

Three checks on def, parameters and calls.

What does def do?

def creates the function and gives it a name. A call runs it later.

In the call move_right(8), what value does steps receive?

The argument 8 fills the parameter steps for that call.

What happens if you call a function before its def line?

Python needs the definition before it can run the call. Define first, call second.

Require the reason as well as the letter. The rules: def defines, the argument fills the parameter, and definitions must come before calls. If time allows, ask students to write the two-line helper from memory on a whiteboard, then compare with the slide. This is the last quiz before the game, so it is also a readiness check.
